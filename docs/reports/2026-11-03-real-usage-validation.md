## 优先修复的问题

### 用户回复没有进入验收证据

复现流程：提交“姓名尚未提供，必须先询问，收到回复后写问候文件”的任务；Rocky 询问姓名；在问题卡片回复“小林”。消息接口返回 `delivery_status=consumed`，并绑定 `question-1`；界面显示“小林 已纳入执行”。随后文件确实写成了“你好，小林！这是 Rocky 的真实使用测试。”。

验收却反馈“证据仅显示写入和读取文件，没有询问姓名或用户明确回复的记录，无法确认‘小林’由用户提供”。任务因此再次询问同一姓名，新的问题 ID 为 `question-5`。这不是消息未送达：执行模型已使用回复，缺失的是验收模型及确定性审计可引用的交互证据。

代码定位：[Activities.review_evidence](../../src/rocky/activities.py#L232) 只收集执行步骤；[collect_review_evidence](../../src/rocky/evidence.py#L95) 只纳入有 action/result 的工具操作，不纳入问题和持久化用户回复；[review](../../src/rocky/planner.py#L1264) 的请求清除 checkpoint，也未另加用户回复证据。使用真实步骤重放证据收集器，输出中确实没有“小林”，而消息表已有 consumed 回复。

建议将应用记录的提问、问题 ID、用户回答及接收时间作为独立、可引用的可信证据传给验收，并接入确定性审计索引。不能让模型自己写一份“用户说过”的文件来代替交互证据。

### 有效断言被误判为直接写出答案

主任务第 12 轮验收中，模型已认为四份交付完整一致、实际执行与核验成功；确定性证据审计却报：`the command states this value literally instead of computing it`。命令实际读取 CSV、计算汇总，再与预期值做断言。预期值出现在断言中，不代表输出没有经过计算。

代码定位：[evidence.py](../../src/rocky/evidence.py#L443)。`computed` 证据只要在命令文本中找到所报值就直接拒绝。离线最小复现先实际执行以下代码，输出 `A: 37.50`，再把结果交给 `_audit_claim`，仍稳定收到上述拒绝：

```python
total = sum([25.00, 12.50])
assert total == 37.50
print(f"A: {total:.2f}")
```

首轮第 10 轮还有一次模型自身的证据判断失败：它引用了实际存在的汇总代码，却标记没有支持证据。两次验收失败共同消耗了 AI 估计的 12 步预算；加倍预算后，Rocky 改用不含明确预期值的重算命令，才完成交付。此行为已保存为证据，不代表每次模型运行都会出现相同失败。

建议区分计算输出与断言常量；保留防止伪造结果的审计，同时允许真实计算加预期断言的常见核验方式，并为本次案例加入回归覆盖。

### 无效凭据只显示通用错误

第一次从界面提交任务立即失败，只提示“AI 未能完成任务评估，请检查模型配置后重新提交”。单独检查确认 Rocky 已保存的密钥返回 `401 invalid_api_key`，而用户授权复用的环境密钥可访问同一模型。按用户明确授权替换钥匙串中的无效密钥后，原任务正常起草并执行。

这是本机配置问题，现已处理；产品诊断仍有改进空间。[API](../../src/rocky/api.py#L506) 把所有 `PlannerError` 统一变成 502，[客户端](../../desktop/Sources/RockyDesktop/APIClient.swift#L35) 只按状态码给通用提示。建议保留经过脱敏的错误类别，分别提示凭据无效、模型无权限、限流或网络故障，避免用户无依据地反复重试。

## 需要复核的界面现象

默认“关闭窗口后留在菜单栏”开启时，关闭主窗口后，通过 Finder 两次重新打开 `Rocky.app`，自动化均未获取到恢复的主窗口；完整退出客户端再启动则立即恢复。后台任务始终保留。此现象需要人工核对菜单栏“打开 Rocky”和 Dock 重开路径，不能仅凭自动化超时确定所有重新打开路径都有缺陷。
