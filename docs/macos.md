# Rocky for macOS

Rocky 只提供 macOS 原生客户端，使用 SwiftUI。任务历史、任务输入、执行记录、产物和模型配置都在本机窗口中完成；Python 执行内核负责持久化、工具权限和结果核验。

界面使用黑白灰中性色，随系统浅色或深色外观自动适配。新任务页的输入区居中显示；进入任务后，补充输入固定在底部。主操作使用黑白反色按钮，橙色和红色保留用于等待处理、警告及错误状态。

## 安装与首次打开

需要 macOS 14 或更新版本。开发构建支持当前 Mac 的处理器架构。

在项目根目录运行：

```bash
./scripts/build_macos.sh
open dist/Rocky.app
```

构建需要 Xcode Command Line Tools 和网络连接；脚本会准备应用需要的运行工具并生成 `dist/Rocky.app`。可以将应用拖到“应用程序”文件夹后使用。应用内置 Python 和全部锁定的依赖：首次打开或升级后，应用在用户的 Application Support 目录离线准备运行环境，随后启动本地 API、任务 worker 和持久化 Temporal 服务；同一版本再次启动时直接运行，不调用 uv、不需要网络。设置 `ROCKY_SKIP_OFFLINE_BUNDLE=1` 构建的应用体积更小，但首次准备需要访问 PyPI 和 GitHub。之后无需保留终端或打开浏览器。

这是本机构建并临时签名的应用。面向其他用户分发的版本仍需要开发者自己的 Developer ID 签名和 Apple 公证。

## 配置模型

点击左下角“设置与模型”，或按 `⌘,`，选择服务商后从“模型名称”下拉菜单选择模型，确认 API Base URL 并填写 API key，然后保存。列表提供各服务的常用模型；实际可用性取决于服务权限或本机已安装的模型。未列出的模型可通过“自定义模型…”填写，已保存的自定义模型也会保留在下拉菜单中。

“思考程度”下拉菜单按所选模型支持的档位显示，默认使用“模型默认”。切换模型时，不兼容的思考档位会自动恢复默认；没有可配置档位的模型不显示该设置，使用模型默认。

密钥字段不会重新显示已保存的值；保留为空可以继续使用该配置原有的密钥。需要更换密钥时填入新值，需要删除时勾选“移除当前服务已保存的密钥”后保存。

- **OpenAI 兼容服务**：适用于 DeepSeek、OpenRouter 及提供 Chat Completions 兼容接口的其他服务。使用服务商给出的 API Base URL，模型 ID 必须与服务商提供的名称一致。
- **Anthropic**：使用 Messages API，可填写 Anthropic 或兼容该协议的服务地址。
- **Ollama**：先运行本机 Ollama 并准备模型，再选择其 OpenAI 兼容地址（通常为 `http://localhost:11434/v1`）。本地模型可以不设置 API key。
- **OpenAI**：保留原有 Responses API 支持及适用模型的思考级别配置。

Base URL 填写 API 的基础地址，不要在地址中放置用户名、密码或密钥。远程模型服务需要 HTTPS；本机服务可使用 HTTP。模型必须能返回应用所需的结构化 JSON；协议兼容不意味着所有服务商的所有模型均支持相同能力。

macOS 版本将密钥保存到系统钥匙串，任务数据库只记录服务商、模型和凭证引用。模型密钥不会写入任务提示、任务事件或设置接口返回值。更换默认模型只影响后续创建的任务；已创建任务使用提交时记录的模型配置。

## 执行诊断与模型排队

打开任务后，Rocky 回复下方的诊断卡片会说明当前在等待执行进程、等待模型名额、请求模型、执行工具、退避重试，还是等待你的回复；同时显示当前阶段持续时间、剩余步骤／调用／token 预算，以及可用运行时间。等待人工批准或补充资料时，运行计时暂停。这里的步骤和调用数是预算余量，已经扣除当前轮的预留，不是待完成事项数量。

“设置与模型 → 模型调用调度”显示整台后台服务的运行和排队数量。合同生成、长期目标准备、重规划、任务规划和验收共享总限额，默认同时 4 次，其中普通请求最多占 3 次，为人工追加消息及手动拟定任务要求预留 1 个名额。追加消息下一轮进入独立接收队列，之后回归普通队列；正在执行的请求继续完成。队列等待仍计入任务运行时限，系统不保证立即完成响应。

开发配置 `ROCKY_MAX_CONCURRENT_MODEL_CALLS` 控制总限额，`ROCKY_MODEL_INTERACTIVE_RESERVE` 控制预留数（默认 1；总限额为 1 时自动不预留，始终保留至少一个普通名额）。更改服务配置并重启后生效。调低限额会等待已有调用完成再按新限额接收请求。

## 提示词与领域指导

在“设置与模型 → 执行指导”中点“查看提示词与技能…”，可以查看 9 个内置模块的内容、版本和摘要，并预览执行规划、独立验收、任务要求、目标拆解和计划调整的组合指令及输出结构。预览不调用模型；其中的编程、研究选项只影响预览。实际规划按已确认的目标、验收标准和交付文件类型匹配固定领域指导，文件内容、网页和记忆不能导入新指令，也不会因此获得额外权限。

任务详情中的“查看提示词版本…”列出该任务请求开始前保存的版本。同一组合重复使用只更新最近记录时间；升级后使用的新版本会另列，旧内容保留，可查看与已安装模块的指令和输出结构差异。记录不代表模型请求成功，也不包括任务输入、文件内容、密钥或服务商协议封装。早期任务没有历史记录；继续产生新请求后才会记录，不会把当前版本伪填为过去使用的版本。

## 提交任务

“议程”（`⌘⇧L`）的“事件任务”页可以在文件变化或外部事件到来时启动任务。新建时填写要完成的事，查看 AI 拟定的验收标准、交付文件和每次运行预算，再保存为“仅观察”。此模式只记录建议，不创建任务，也不调用执行模型；可在触发记录中执行某次建议或忽略，也可检查合适后将规则切为“自动执行”。实际任务继续遵守原有权限和操作审批。

文件来源只监听选中的一个文件，并把它作为任务的只读参考资料；首次检查只建立基线，之后文件的修改时间、大小或身份发生变化并稳定 30 秒后触发（每 5 秒检查）。关闭或更改模式后会重新建立基线，不追补关闭期间的变化。上次任务未结束时，新事件只记录“本次未启动”，不排成长队；可以在上次结束后手动执行这条建议。移除规则会保留已运行的任务和触发记录。

“事件任务”将“待处理建议”和“触发历史”分开展示，每页 25 条。待处理建议从最早收到的开始，待办总数包含所有页面；较早的建议不会因为新增记录而消失。历史从最新记录开始，可前后翻页或回到最新；后台刷新保留当前页。关闭、移除或更新规则后，旧版本建议保留在历史中，可以忽略；执行时仍会检查规则版本和上次任务状态。

新建规则可设置每日自动启动上限，默认 5 次，范围 1–100 次，按创建时的本机时区每日零点重置。已有规则默认使用 UTC，可点“自动启动额度…”修改上限和时区。页面显示当天自动启动次数；已存在的自动启动记录也参与统计。重启和切换模式不会清空记录，重复投递同一事件不会重复计数。达到上限时只记录建议，可手动执行或忽略，手动执行不占自动额度。次日只有新事件才可能自动启动，旧事件不会补跑；每次任务仍使用已确认的合同和预算。修改额度会更新规则版本，旧建议保留在历史中。

长期目标的合同生成和后续重规划在独立的后台操作中进行；准备好的下一步会显示“已准备，等待名额”。准备结果会保存，后台服务重启后可以直接启动，无需重复生成合同。

按 `⌘N` 新建任务，输入要完成的目标，按 `⌘↩` 提交。提交时会使用已配置的模型和密钥，根据目标生成验收标准和产物路径，并按任务难度自动分配步骤、模型调用、累计输入/输出 token 和运行时间，无需手动设置。简单任务使用较少预算，复杂任务保留更多执行、独立验收及修复空间。自动预算始终有限，最高为 100 步、150 次模型调用、5000000 个累计 token 和 60 分钟，后端会校验这些上限，并按预计调用次数为重复上下文、独立验收及修复保留预算，避免把最终答复长度误当作整个任务的 token 消耗。评估失败时会提示重新提交；任务创建前的评估调用不计入任务执行用量。生成后不会立即提交，而是先弹出“提交前核对”：列出验收标准、交付文件和预算，并提醒需要注意的地方，例如某条标准无法客观核验、目标依赖 Rocky 拿不到的资料或账号，或预算与调用次数不匹配。提醒不会阻止提交；可以“返回修改”目标，也可以把预算调到 2 倍或 4 倍、把时限调到最多 8 小时或不限，再点“提交任务”。时限只算 Rocky 自己工作的时间，等你审批或补充信息时暂停计时。交付要求、预算和实际用量提交后可在任务详情中查看。每个任务有默认工作目录，交付产物路径相对于该目录。

输入框可以拖入文件夹（授权任务直接修改其中的文件）或文件（作为参考资料，任务可以读取但不修改）；也可以点文件夹按钮选择。提交前的核对页可以直接修改、删除或补充验收标准和交付文件，并显示拟定这份核对单用了多少 tokens（不计入任务预算）。

## 权限与审批

侧栏的“待你处理”集中显示需要批准的操作、待回答的问题、超时未批操作、需要恢复或追加预算的任务、待审阅的交付，以及需要处理的长期目标。查看结果后仍保留待办，明确点击“接受结果”才会移除该轮交付；审阅决定保存在本机后台服务中，重启应用后仍保留。审批设置仍在“审批”中管理。

Rocky 缺少必要资料时会显示独立的问题卡片，可选择建议答案或填写其他回答，再点“回答并继续”。回答绑定当时的问题，旧问题不能回答到新问题上；回答问题不会批准 Shell 命令或网络写入，操作授权仍需使用审批卡片。

任务中的补充信息显示“已保存，等待送达”“已送达，等待模型读取”或“已纳入执行”。只有完整消息实际进入一次成功的模型规划请求并记录后才确认已纳入执行；被上下文截断或尚未读取的消息不会被误标。旧版记录无法确认读取状态时会如实显示“读取状态未知”。执行器收到新消息后，会在后续动作或报告成功前重新规划。

桌面版默认完整工具权限：Rocky 可以运行 Shell/Python、安装任务依赖、访问任意网站或本机服务，提交 POST 等 HTTP 请求并保持登录会话，无需配置工具和域名白名单，旧任务中保存的白名单也不再限制执行。文件方面，任务目录和授权文件夹内可直接读写，家目录之外的系统和工具链文件可直接读取；写到这些范围之外、读取家目录下的其他个人文件或凭据存储（`~/.ssh`、钥匙串、浏览器配置等），都需要你逐次批准。登录时使用任务提供的账号信息，Cookie 按任务持久保存，重启后可以继续使用。需要验证码、MFA 或 macOS 系统授权时，仍由用户完成对应操作。

默认审批模式下，每条 Shell 命令，以及 GET/HEAD/OPTIONS 以外的 HTTP 请求，执行前都会出现“批准此操作”卡片，展示工具、路径、网址和完整参数。确认后点击批准，Rocky 继续执行同一操作；也可在本任务内批准同类操作、点“以后始终允许”保存为规则、拒绝，或点击“停止任务”。沙箱内的只读命令（`ls`、`cat`、`grep` 等）默认直接执行。无人回应的请求默认 30 分钟后自动拒绝（不会自动批准），任务改做其他工作，该操作留在左侧“审批”中，可补批后原样执行一次。“审批”页还能多选批量处理、调整超时时长（选“一直等待”时任务会等到你处理，期间不计时）、关闭只读放行，以及手动添加或删除“始终允许”的命令规则；常用的测试和构建命令（如 `uv run pytest`、`npm test`、`swift test`）可一键添加。规则只在沙箱内放行；沙箱外命令、写到任务目录和授权文件夹以外的文件、读取凭据和家目录下其他个人文件始终逐条批准。审批只对该具体操作生效，普通聊天中的“继续”不能代替批准。等待审批时不会继续调用模型。

## 继续任务

达到步数、调用或 token 上限会显示“已达预算上限”，达到时限会显示“已到截止时间”；这两种任务可点击“加倍预算继续”或“延长时限继续”：在原任务上接着做，沿用工作区、进度、交接摘要和执行记录，每个有限的上限翻倍（不超过重试上限），运行时间重新计算。已完成、已停止或到达上限的任务，可以直接在输入框写追加要求（例如“把第三节展开一点”）：Rocky 在同一个任务上继续，要求会并入目标和验收标准，并在已用量之上再给一份原预算。只有失败的任务需要先恢复。提供方返回的 token 用量在调用之后才可确认，一次进行中的请求可能越过阈值；未返回用量的请求仍累计调用次数。

任务执行中会显示状态、工具记录和实际用量。规划上下文采用交接摘要、最新结果与旧结果节选，代码可按行读取；目标、验收标准和必要的用户补充仍保留，完整执行证据不会因上下文压缩而删除。任务等待补充信息时，在原任务中输入反馈并继续；它沿用原有工作目录和执行记录。停止操作会提交取消命令，待 worker 确认后显示最终状态。已发生的写入和已发送的模型请求不会撤销。

## 查看结果

执行记录按步骤卡片展示，同一步的并行操作合并排列，省略重复的运行检查点，并保留错误、暂停和产物变化。每项操作默认展示摘要，结果按需展开；命令的执行状态、标准输出和错误输出分区展示，结构化响应会格式化，长内容在限定高度内滚动。聊天快照中的长结果可能是节选，完整执行证据仍保存在本机记录中。

产物来自任务实际写入的文件，模型的进度说明不代表产物已通过验证。只有确定性文件检查和独立模型核验都通过后，任务才显示完成。产物卡片可预览并另存文件；长文件的预览会明确标记截断，另存操作下载完整文件。任务详情也可在 Finder 中打开工作目录。

完成任务的“交付待审阅”卡片提供“接受结果”和“要求修改”。接受只记录你的审阅决定，不调用模型；修改时填写具体要求，提交后沿用原任务的工作区和进度，在已用量之上再给一份当前预算并重新计时。修改要求与审阅的版本绑定，重复提交同一要求不会重复续做；如果已有新一轮执行或交付，需要先刷新再审阅。已接受的任务仍可在输入框中追加新要求。人工接受与执行完成是两个独立状态，议程仍按执行核验成功推进后续步骤。

“查看交付历史…”按轮展示当时的交付要求、总结、独立验收反馈和你的审阅记录。新交付在报告成功前保存所有已核验产物的文件快照，可以分版本预览和导出；后续修改同一路径的文件不会覆盖旧版。只保存该轮核验的交付文件，不复制整个工作目录。文件原件缺失或完整性校验失败时会提示，不能以当前文件冒充旧版。

升级前的任务没有历史文件快照，界面会明确说明；当前版本仅在文件仍与原核验记录一致时可读取，接受或追加修改前会尝试保存这些文件。缺失或已变化的旧文件不能直接接受，可要求修改后重新核验。旧版客户端的“已查看”记录不会被当作人工接受。存档保留交付历史，删除任务会同时删除历史和文件快照。

任务完成后，界面显示 Rocky 写给你的结果总结；系统提示（如到达上限、等待批准）显示为中文。侧栏始终列出所有未完成的任务，搜索会查找全部任务。窗口不在前台时，应用降低刷新频率，但仍会发送通知。

## 通知与后台服务

任务需要审批、等你回复或结束时，Rocky 发送系统通知（点通知直接打开该任务），Dock 图标显示等你处理的任务数；任务一直等你时每 3 小时再提醒一次。默认关闭窗口后 Rocky 留在菜单栏继续接收通知，菜单里列出等你处理的任务；可在“设置与模型 → 通知”关闭，关闭后关窗口即退出应用（后台服务照常运行，但不再提醒）。

Rocky 的执行内核作为后台服务（launchd 用户级 LaunchAgent `dev.rocky.agent`）常驻运行，由应用通过 `SMAppService` 注册，可在“系统设置 > 通用 > 登录项与扩展”中查看或关闭。关闭窗口或退出 Rocky 不会停止后台服务，任务继续执行；重新打开应用会直接连接。后台服务在用户登录期间运行，崩溃后由 launchd 自动重启，未结束的任务从执行检查点恢复。有任务处于排队或运行状态时，后台服务会阻止 Mac 空闲睡眠；合盖或手动睡眠时任务暂停，唤醒后继续，配置的任务时限包含暂停期间。设置中的“后台服务”可重启或停止服务；停止后未结束任务暂停，再次打开应用或点击“启动后台服务”即可恢复。升级应用后首次打开时，应用会自动重启后台服务以加载新版本，进行中的任务从检查点恢复。

## 管理已结束的任务

已结束任务可在侧栏右键菜单或顶栏的存档、删除按钮中管理。存档后可在侧栏切换到“已存档”，查看记录或恢复。删除需要确认，会移除任务、执行记录和工作区文件（含交付物），且无法撤销；只想移出列表请用存档。确认框里可以先在 Finder 中查看文件。进行中、休眠和等待输入的任务需先停止才能管理。

## 长期记忆

Rocky 规划任务时会参考相关的长期记忆（你的偏好、反复适用的决定、更正和踩过的坑）。任务完成或停下来等你时，Rocky 可能建议最多三条新记忆，显示在该任务结果下方；可以先修改文字再点“保存”，或点“忽略”（同一任务不会再建议）。没有你的确认，任何内容都不会写入长期记忆。“设置 › 长期记忆”列出已保存的记忆，可以手动添加或删除。

## 本机数据与运行状态

默认数据目录：

```text
~/Library/Application Support/Rocky/
```

该目录保存本地数据库、任务工作目录、Temporal 历史、备份及运行环境。钥匙串凭证单独保存在系统钥匙串中。后台服务每天自动备份数据库和任务文件夹到 `backups/`，保留最近 7 份；“设置 → 运行状态与备份”可以立即备份、查看执行进程和磁盘状态。恢复时先停止后台服务，再在终端运行 `rocky restore <备份文件>`，当前数据会移到 `data/pre-restore-<时间>/` 保留。

后台服务只监听回环地址，API 始终要求保存在 `data/api-token`（权限 0600）的持久令牌。应用只连接自己注册的后台服务，不会接管其他外部服务。同一数据目录一次只允许一个服务实例（`run/service.lock`）；若端口已被其他进程占用，后台服务会启动失败并由 launchd 定期重试。运行日志位于 `logs/`（`agent.log`、`temporal.log`、`api.log`、`worker.log`，上一轮或超过 20 MB 的部分保留为 `.1`），当前阶段写入 `run/status`，执行进程每 15 秒写一次 `run/worker-heartbeat`。

启动失败时可从应用中重试，并检查网络连接、磁盘空间及运行日志。不要删除数据目录来解决普通连接错误。删除目录会丢失任务与产物；清除钥匙串凭证需要单独操作。

在“设置 → 运行状态与备份 → 存储与诊断…”中，可分别查看任务工作区、交付文件快照、任务运行数据、数据库与执行历史、备份和日志的磁盘占用与文件数。工作区包含依赖和缓存，任务运行数据包含操作回执与浏览器会话，已存档任务也参与统计。应用、运行环境、外部授权文件夹和符号链接目标不计入；数据库只统计本机 SQLite 文件及其辅助文件。用量根据文件已分配空间估算，硬链接只计一次，文件系统共享空间可能使它与 Finder 不同。

统计在打开页面或点击“刷新统计”时按需进行，最多缓存 60 秒，不随任务刷新持续扫描。单次扫描预算为 3 秒、100,000 个目录项目和 64 层目录；达到上限、权限不足或扫描期间文件变化时，会明确显示部分结果及原因。刷新失败会保留上次统计。统计不会删除文件或清理交付历史；释放空间可使用已有的任务删除功能，存档本身不会释放空间。

“导出脱敏诊断包…”会将 ZIP 保存到你选择的位置，不调用模型或自动上传。包中只有 `report.json` 和说明文件，包含应用与 Python 版本、系统与处理器类型、服务和执行引擎状态、任务数量、模型排队数量、空间统计及少量运行选项。不会包含任务内容、产物、文件名与路径、原始日志、数据库副本、模型配置、密钥、API 令牌、Cookie 或环境变量。后台部分信息无法读取时仍会尽量导出，用 `unavailable_components` 标明缺项，不包含原始异常。导出需要能连接本地 API；诊断包不是备份，不能用于恢复任务。

## 开发与验证

Swift 源码在 `desktop/Sources/RockyDesktop/`，后端在 `src/rocky/`。桌面客户端通过本地 HTTP API 访问任务；单独调试后端时可使用 CLI。

```bash
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q -m 'not integration'
swift test --package-path desktop
./scripts/build_macos.sh
```

第三方服务适配测试使用模拟响应，无需真实密钥，不产生模型费用。实际模型的可用性、速率限制、权限和费用由所选服务商决定。
