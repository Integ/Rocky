# 可靠性验证

真实模型的任务成功率由 [评测集](../evals/README.md) 衡量。服务持久性另外使用
`scripts/run_reliability.py`：启动独立的 API、worker 和持久化 Temporal 子进程，
使用本地脚本化模型返回固定决策，不调用外部模型、不继承当前环境中的 API 密钥。
已有应用的任务、模型设置和后台服务不参与验证。

## 执行

需要 macOS、项目开发依赖和 Temporal CLI。可以使用已构建应用内的 Temporal：

```bash
uv run python scripts/run_reliability.py --cycles 3 \
  --temporal-binary dist/Rocky.app/Contents/Resources/runtime/bin/temporal
```

持续运行模式，每 5 分钟开始一个周期，在周期间继续采集服务状态与内存：

```bash
uv run python scripts/run_reliability.py --duration-hours 24 \
  --cycle-interval-seconds 300 \
  --temporal-binary dist/Rocky.app/Contents/Resources/runtime/bin/temporal
```

运行目录默认在系统临时目录，新建且必须位于代码仓库之外；可用 `--run-dir` 指定不存在的
绝对路径。运行结束或失败后停止自己的服务进程。保留 `report.json`、`samples.jsonl`、
服务日志、数据库、合成工作区和最近两份备份。中途记录的 `passed=false/state=running`
不能当作最终通过；应以进程退出码 0 和最终 `state=passed` 为准。

脚本只自动批准自身固定的合成命令 `printf 'verified\n' > marker.txt`，不会生成任意命令。
备份恢复后先确认旧数据被保留，再删除本次合成的 pre-restore 副本，避免长跑时磁盘二次增长。

## 每周期核对

1. 实际追加文件，等待命令审批；确认审批前命令文件尚不存在。
2. 轮流强制结束 worker、API 或 Temporal。确认 supervisor 以非零状态退出，再重新启动。
3. 比较审批完整内容、步数、调用和 token 用量；确认重启没有批准操作或重复追加。
4. 对本地模型接口注入两次 HTTP 503。批准原操作，等待恢复完成，逐字比较两个产物。
5. 创建到期的一次性定时任务，确认只启动一次并完成交付。
6. 等待文件监听基线实际保存后修改文件，确认防抖后仅启动一个任务并完成交付。
7. 在空闲检查点备份，停止服务并改动产物，再恢复备份、重新启动，比较原文件哈希和终态。
8. 核对没有未派发任务、未发送指令或待审批操作；对两份 SQLite 数据库执行 `quick_check`。

这些检查证明的是固定合成流程在实际服务上的行为。内存、事件和磁盘数据用于观察趋势，
目前没有资源增长的自动验收阈值。相邻周期会保留历史，持续运行模式能观察累积数据的影响；
频繁注入重启也意味着它不能代替单进程数日不重启的内存泄漏测试。

## 仍须真机核对

以下操作必须单独记录实际结果，不能用模拟时钟、进程重启或自动化测试的通过代替：

| 场景 | 核对内容 |
| --- | --- |
| 合盖与唤醒 | 执行中及等待审批时分别合盖；唤醒后原任务继续，审批不自动放行、文件不重复追加 |
| 系统重启 | 保留一个等待审批任务后重启 Mac；检查 launchd 启动、同一任务与历史、原操作仍待批准 |
| 真正断网 | 真实模型请求中断网再恢复；检查错误提示、有限重试、已知用量和文件状态 |
| 签名与公证 | 在未运行过 Rocky 的另一台 Mac 上安装正式包，核对 Gatekeeper、登录项及后台服务 |
| 钥匙串 | 使用测试账号检查保存、读取、更换、移除及沙箱访问边界；不使用个人真实凭据作探针 |
| 长时间不重启 | 固定负载运行 24–72 小时，观察进程内存、事件/数据库增长及后台响应 |

每份报告应记录提交、构建 ID、系统版本、持续时间、用例结果、日志位置和未覆盖项。
